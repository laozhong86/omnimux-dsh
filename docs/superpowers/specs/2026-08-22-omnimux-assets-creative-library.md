> 状态：**已拍板**（2026-08-22 老板）

> 插件：`omnimux-assets` v0.1.1 → v0.2  
> 参考：老板截图 1（添加资产弹窗）+ 截图 2（资产中心列表）

---

## 0. TL;DR

资产库不再是「把磁盘上的文件/文件夹挂进来」。  
**一条资产 = 有名字、有类型、有描述、可选素材文件的创作对象**，目的是让人和 Agent 在后续创作里按语义复用。

- 默认常驻六类：**角色 / 场景 / 风格包 / 道具 / 知识包 / 自定义**（空也显示）
  - **自定义 = 未选分类**，不是第七种创作语义，也不是另一种存储
- 左侧 `＋` 不再弹出「添加文件 / 添加文件夹」；点 `＋`（以及顶栏「添加资产」）打开创建弹窗
- 创建弹窗对齐截图 1：`@名称` + 类型下拉 + 描述 + 拖入素材 + 可选标签 +「创建资产」
- 列表页对齐截图 2：标题/副标题、主按钮、类型 Chip、搜索、卡片网格
- **所有素材都是路径映射**：只记 `real_path`，**不拷贝、不移动、不改原文件**。路径实体不在磁盘上 → **该素材不显示**（记录可留，路径回来再出现）
- **本轮不做「导入资产包」**（按钮直接不画）

**本轮不做通用文件管理。** 不再把「添加文件夹」当主路径；UI 按创作对象组织，磁盘仍只是引用。

---

## 1. Problem Statement

社媒 / 短剧创作者在 OmniMux 里反复用同一批角色定妆、场景底板、风格提示、道具、品牌知识。  
现在的资产库把这些东西当成「本地文件夹映射」：点 `＋` 只能选文件或文件夹，左侧是自建映射列表，右侧是一层文件表。人要靠路径记住「这是谁」；Agent 只能 `assets_list` 到路径，没有类型、没有描述、没有可引用的名字。

成本：

- 库空时没有任何分类骨架，不知道该往哪放
- 入库摩擦是文件系统动作，不是创作动作
- 后续项目壳 / 画布无法按「角色林晓」取资产，只能按文件名碰运气

不改的话，资产库会继续像一个残缺 Finder，而创作页需要的是「可检索、可 @、可复用的资产对象」。

---

## 2. Goals

1. **身份清晰**：用户能在 10 秒内建一条「有名字 + 有类型」的资产，不必先选磁盘路径。
2. **分类常在**：打开资产库立刻看到六类，空类也在，降低「这是文件夹还是库」的认知负担。
3. **给 Agent 可检索对象**：`assets_list` / `assets_search` 返回名称、类型、描述、素材，而不是映射路径表。
4. **创作页可调用的数据形状**：资产有稳定 `id` 和 `@名称`，后续项目/画布可以引用，本轮至少支持复制引用句。
5. **旧能力不挡路**：原「添加文件/文件夹」退出主 UI；旧 mapping 收成未分类资产（仍只引用原路径，失效则不显示）。

---

## 3. Non-Goals（本轮明确不做）

| 不做 | 原因 |
|---|---|
| 通用文件夹管理 / 递归 Finder | 这正是要离开的产品形态 |
| 云同步、分享链接、多人协作 | local-first；另立项 |
| 自定义类型体系（用户自建第七类） | 六类先验证；溢出进「自定义」 |
| 画布节点拖入 / 项目页选取器完整接入 | 数据先稳定；选取器跟项目壳走，本轮只保证工具 + 复制 `@` |
| 导入 / 导出资产包 | 本轮明确不做，按钮不画 |
| 资产版本历史、A/B 定妆对比 | 过早 |
| 修改或删除用户磁盘上的原始文件 | 红线不变：最多拷贝进插件自有区 |
| 跨插件 import hub 内部模块 | 契约不变 |

## 4. 产品定位与对象模型

### 4.1 一句话

**资产库是创作对象的本地语义库，不是磁盘浏览器。**

### 4.2 术语（禁止混用）

| 中文 | 代码 | 是什么 | 不是什么 |
|---|---|---|---|
| **资产** | `asset` | 一条有 `id/name/type/description/tags/files` 的记录 | 不是文件夹，不是 mapping |
| **类型** | `asset.type` | 六枚举之一 | 不是 MIME（image/mp4） |
| **素材文件** | `asset.files[]` | 挂在这条资产下的参考图/视频/文档 | 不是资产本身 |
| **产物** | `artifact` | Agent `assets_upload` 上报的生成文件 | 本轮退出一级信息架构，可作「收入资产」的来源（P1） |
| **旧映射** | `mapping` | v0.1 挂载的 real_path | 主 UI 不再露出 |

### 4.3 六类（常驻，空也显示）

顺序固定，禁止用户删类、改类名、调序。

| type | 中文 | 这条资产「是」什么 | 素材预期 | 描述写什么（给 Agent） |
|---|---|---|---|---|
| `character` | 角色 | 可反复出镜的人/形象 | 定妆图、三视图、脸部特写 | 年龄外观服装性格，避免漂外观 |
| `scene` | 场景 | 可反复使用的空间/环境 | 空镜、布局、光线参考 | 时间、天气、镜头语言、禁止改的结构 |
| `style` | 风格包 | 一套视觉/运镜语法 | 参考帧、调色、关键词卡 | 必须遵守的风格约束（镜头、色彩、材质） |
| `prop` | 道具 | 关键物件/服装单品 | 产品图、细节特写 | 形制、材质、出现规则 |
| `knowledge` | 知识包 | 给 Agent 读的文本知识 | md/txt/pdf，可无图 | 品牌口吻、禁区、事实、流程 |
| `custom` | 自定义 | **未选择分类**的收口，不是第七种创作类型 | 任意 | 人话说明「什么时候用」；鼓励以后补成前五类 |

截图 2 的 Chip 少了「知识包」。**以老板原文六类为准**，Chip 为：

`全部` · `角色` · `场景` · `风格包` · `道具` · `知识包` · `自定义`

### 4.4 一条资产的字段（v0.2 schema）

```text
Asset {
  id:               "ast_xxxxxxxx"
  name:             string          // 显示名，即 @ 后面那截
  handle:           string          // 规范化后的引用名，默认等于 name
  type:             character|scene|style|prop|knowledge|custom
  description:      string          // 给 Agent 检索/复用；可空但空态要提示补
  tags:             string[]        // 可选
  files:            AssetFile[]     // 0..n；创建时可不传；每条都是路径引用
  cover_file_id:    string | null   // 默认第一张「磁盘上还在」的图
  source:           "manual" | "migrated-mapping" | "artifact"
  created_at, updated_at
}

AssetFile {
  id
  real_path         // 绝对路径；插件不持有副本
  original_name     // 路径末段，展示用
  kind              // image|video|audio|document|other（按扩展名推断）
  // 运行时：stat 失败 → 该条不进入 API 的 visible files，不画在卡片/详情
}
```

引用句（给人复制、给 Agent 识别）：

```text
@角色/林晓
```

工具层同时接受 `id` 与 `handle`。

## 5. User Stories

**作为短剧创作者**，我希望点一下 `＋` 就能建「角色 · 林晓」并写清外观，以便下次出图不再重写提示词。  
**作为短剧创作者**，我希望打开资产库就看到六类，以便知道库是按创作语义组织的，不是空文件夹。  
**作为短剧创作者**，我希望一条资产可以先起名再建素材，以便灵感来了先占位。  
**作为运营**，我希望知识包能只放文字、不强制上传图，以便品牌禁区直接给 Agent。  
**作为在会话里干活的 Agent**，我希望按类型和描述搜索资产，以便引用定妆而不是猜文件名。  
**作为创作者**，我希望卡片上能复制 `@角色/林晓`，以便贴进对话或后续创作页。  
**边界**：同名资产要明确冲突，不能静默覆盖。  
**边界**：创建时没传文件也可以保存，卡片走类型占位封面。  
**边界**：删除资产只删库记录（`library.json` 一行），**永不碰 `real_path` 上的原文件**。失效路径本来就不显示，删除确认文案仍要写「不会删除磁盘上的原文件」。

## 6. 界面与交互（对齐两张截图）

### 6.1 一级页结构（取代左导航 + 文件表）

去掉：左侧「本地文件夹」组、`添加文件/添加文件夹` 菜单、右侧文件表、产物类型 Chip。

改为单栏「资产中心」：

1. **顶栏**（沿用一级页 chrome：上 12 / 左右 20 / 下 12）
   - 标题：资产库
   - 副标题：沉淀可复用的角色、场景、风格包、道具、知识包，在创作页里给 Agent 引用
   - 关闭
2. **动作行**
   - 主按钮（黑胶囊）：`+ 添加资产`
   - **不画**「导入资产包」（本轮明确不做）
3. **过滤行**
   - 左：类型 Chip（全部 + 六类）
   - 右：搜索框「搜索资产」+ 排序「最近更新」（P1 再加名称）
   - 视图切换网格/列表：P1，默认网格
4. **内容**
   - 卡片网格。空库 / 当前类型为空：保留该类 Chip，网格里一张虚线空态「还没有角色，点击添加资产」
5. **左侧 `＋`**
   - 若一级页仍保留极简左栏（六类树），组头 `＋` **只打开同一创建弹窗**，不再出两项菜单
   - 推荐本轮：**不保留左栏映射列表**；六类用顶部 Chip。左栏如保留，只放六类常驻项（可显示条数），点类 = 过滤

### 6.2 创建弹窗（截图 1，P0）

尺寸：居中 overlay，`--omx-radius-lg`，遮罩 `--omx-color-overlay`。

| 区域 | 行为 |
|---|---|
| 顶行 | `@` 前缀（装饰）+ 名称输入（自动聚焦）+ 关闭 |
| 第二行 | 类型下拉（默认 **角色**）\| 描述 placeholder：「输入清晰的描述，帮助 agent 更好地搜索和复用…」 |
| 中部 | 虚线投放区：「将素材文件拖入/点击上传」。多文件。点区走系统选择窗（继续用现有 macOS picker，kind=file，可多选若平台允许；否则多次添加） |
| 下部 | 折叠「添加标签（可选）」 |
| 右下 | 主按钮「创建资产」；名称为空时禁用 |

校验：

- 名称必填，trim 后 1–40 字，不能含 `/` 与控制字符
- 类型必选，默认 character
- 描述可选，建议 4000 字上限
- 文件可选；选中后只记下绝对路径，不拷贝。路径在创建瞬间不存在则拒绝加入该条素材（可继续创建资产）
- 同 handle 冲突：提示「已有同名资产」，要求改名

创建成功：关弹窗，切到该类型过滤，滚动到新卡片。

编辑：点卡片进详情（P0 最小：右侧或第二层弹窗改名称/类型/描述/标签/增删素材）。本轮不要做成文件夹钻取。

### 6.3 资产卡片（截图 2）

- 封面：第一条**磁盘上仍存在**的图片路径（file:// 或后续缩略图接口）；全都失效或无图 → 类型色块占位；知识包用文档图标
- 左上类型章（角色/场景/…）；`custom` 显示「自定义」
- 标题 = name
- 副文案 = description 一行省略
- 悬停操作：复制引用、删除（确认：「只从资产库移除，不会删除你磁盘上的原文件」）
- 下载/分享本轮不做（分享不在范围；下载等于打开原路径，P1）
- 素材全部失效时：资产卡片仍在（名称/描述还在），封面上标注「素材缺失」，不从列表消失——消失的是文件预览，不是资产身份

### 6.4 空态文案

- 全部为空：「还没有创作资产。点右上角添加资产，先建一个角色或知识包。」
- 某类为空：「还没有{类名}。」 + 按钮「添加{类名}」（打开弹窗且类型预填）

## 7. 业务逻辑

### 7.1 创建

```text
打开弹窗（类型可预填；不选类型 = custom）
  → 填 name / type / description / tags / 本地路径
  → POST /omnimux/assets/library
  → 名称规范化 handle
  → 每条素材只写 real_path（validate: 存在才进入 visible）
  → 不 copy、不 move
  → revision++
  → 返回 asset
```

素材不是资产：一个角色可以有 3 张定妆引用；一张图不能自己变成「角色」除非用户创建时只挂了它。

**路径失效规则（老板拍板）**：`stat` 失败的素材 **不显示**（预览、文件列表、Agent `files` 可见集都不含它）。资产记录本身保留。路径回来后下次刷新自动出现。整条资产没有可见素材时仍列出，卡片走占位封面。

### 7.2 过滤 / 搜索

- Chip：精确 type；「全部」不过滤
- 搜索：`name` `description` `tags` `handle` 大小写不敏感包含匹配（P0 本地）
- 排序默认 `updated_at` 倒序

### 7.3 删除

只删 `library` 记录 + 插件目录里该资产的文件拷贝。  
**永不 rm 用户原路径。** 文案必须写明。

### 7.4 Agent 工具调整

| 工具 | v0.1 | v0.2 |
|---|---|---|
| `assets_list` | mappings / mapping_files / artifacts | **主路径 `scope=assets`**（可 `type`）；旧 scope 保留但描述标明 deprecated |
| `assets_search` | 无 | 新：query + 可选 type |
| `assets_get` | 无 | 按 id 或 handle 取完整资产（含描述与文件路径） |
| `assets_upload` | 写入产物索引 | 仍写入产物；**不自动冒充某类资产**。P1 提供「收入为资产」 |

系统提示改成：先按类型和描述找资产；引用时带 `@类型/名称` 和 description；不要把资产库当工作区 cd。

### 7.5 与项目壳 / 画布

本轮契约：资产 `id` 稳定，可供后续 `omnimux-workflow` 选取。  
本轮 UI 不进画布。复制 `@类型/名称` 足够把引用打进会话。

## 8. 存储与红线

仍只写 `$DSH_HOME/omnimux/assets/`：

```text
omnimux/assets/
  library.json          # schema 2，assets[] + revision；素材只有 real_path
  mappings.json         # v0.1；启动时迁成 custom 资产后可停写
  artifacts.json        # 产物仍在，一级页不再作为主视图
```

**红线：**

- 插件对用户素材路径 **只读**（`stat` / 读缩略图），禁止 copy / rename / unlink
- 删除资产 = 删 JSON 记录，禁止 `rm` `real_path`
- 不 import hub
- POST 仍走 loopback 写校验
- 权限：目录 `0700`，JSON `0600`
