# 增量 PRD：计费入口余额预检

> 本文只记录相对一期统一额度门的变更。它不改一期 PRD 正文、不代替架构设计，也不改变云端计费规则。

## 1. 相对一期的变更摘要

一期 §9 将“余额实时预检”列为非目标；本增量正式翻案：对已识别的客户端计费入口，在真正发起云请求前增加“余额预检”。预检的职责是提前阻止已知余额不足的操作，减少用户等待和无效请求；它不是计费授权，也不是 402 的替代品。

以下一期决策全部继续有效：

- 已上线的 `window.__omnimuxQuota` 失败后统一弹窗保留，覆盖云端 402、`insufficient_user_quota`、预扣费失败等兜底情形。
- 预检确认余额不足时弹同一扇“可用额度不足”窗，主 CTA 为“去充值”，进入钱包；原操作停住，不自动重试、不硬打云。
- 垂直不 import hub、不新增 Settings section；Agent 工具只返回结构化额度错误，不弹窗。
- 不内嵌收银台，不修改云计费和扣费口径。创建项目（本地文件夹）不预检。

本增量新增的核心体验规则：数据分析打开即预检；连接账号、发布、生成类写操作在用户点击 CTA 时预检；预检无法可靠完成时默认放行实际请求，让一期 402 兜底，而不是把网络故障误报成余额不足。

## 2. 产品目标 + 用户故事

### 2.1 Product Goals

1. **提前止损**：对明确余额为零/不足的客户端计费操作，在云请求前阻断，降低无效等待与困惑。
2. **不误伤可用用户**：缓存过期、status 校验失败、超时或预估不可得不能被伪装成“余额不足”；实际请求仍由一期 402 门保护。
3. **体验一致且可恢复**：预检与失败兜底使用同一额度门、同一钱包 URL、同一去重/冷却规则；关闭或充值返回后由用户再次明确点击，不自动重试。

### 2.2 User Stories

- 作为数据分析用户，我希望打开分析页前就知道余额是否可用，以便不在空白加载页上等待一次必然失败的云请求。
- 作为账号运营者，我希望点击“连接账号”或“发布”时先检查余额，以便不会提交到一半才发现额度不足。
- 作为创作者，我希望余额不足时看到统一的“可用额度不足”窗并能去充值，以便知道下一步怎么做。
- 作为余额刚变化或多窗口使用的用户，我希望系统尽量读取新余额，同时不因短暂网络问题把我锁在充值门外。
- 作为 Agent/Chat 用户，我希望工具和会话仍遵循既有结构化错误/失败态边界，不被客户端额度门打断。

## 3. 预检策略（数据源、阈值、失败降级）

### 3.1 数据源与新鲜度

- 权威字段仍是 `/omnimux/auth/status?verify=1` 返回的公开 `quota_usd`；其换算真源为 `云 quota / 500000`，`used_quota_usd` 仅用于展示，不参与放行判断。
- `quota_usd` 的普通 status 缓存可用于页面展示和预检前的快速登录判断，但不能单独作为“余额足够”的最终证据。
- 对每个受保护入口，使用共享的 verify 请求：若同一会话中的成功 verify 结果年龄不超过 **30 秒**，复用该结果；超过 30 秒、登录切换、收到 402、从钱包返回或用户明确点击“再试一次”时强制刷新。相同时间窗口的并发请求合并为一个 inflight，避免多窗口/多组件重复打云。
- verify 结果按会话共享，不跨用户、不跨 profile；旧窗口收到新结果后只更新本地视图，不覆盖更新鲜的余额。收到成功登录后立即清除旧额度快照并重新取得。
- 预检不把余额写回业务库，不改变 Profile 的展示语义。Profile 页面若另有刷新策略，本 PRD 不假设相关 worktree 已合入。

### 3.2 阈值与未知费用

- P0 阈值裁定为 `quota_usd <= 0`（包括明确的零值）；`null`、非数字、负数之外的未知值不直接判定不足。
- 本期不采用“余额小于本次预估费用”作为通用阻断条件：各能力没有稳定、可由客户端复现的费用估价，尤其视频生成费用随模型、时长、供应商和任务阶段变化。
- 因而图片、视频、文本、分析、连接和发布均采用“可用余额大于 0 即通过预检”的保守策略；通过后仍可能被并发扣费或云端预扣费拒绝，必须走一期 402 兜底。
- `quota_usd` 很低但大于 0：P0 不弹不足窗；P1 可在已存在余额展示位置给出非阻断的“余额较低”提示，但不得在每个入口反复打扰，不得声称本次一定够用。
- 没有可靠预估费用时不得把“无法估价”当余额不足；只要登录和预检请求成功且余额为正，就允许发起实际操作。

### 3.3 登录、预检失败与降级

- 未登录或登录状态不确定时，先走一期 `__omnimuxAuth.ensureLogin()` 登录门，绝不先打开充值门。登录成功后不自动重放原操作；用户需再次点击，入口再执行预检。
- verify 明确返回余额为零/负数：预检失败，弹一期同一额度窗，原操作不发出。
- verify 返回 401/`needs-omnimux`：交给登录门；不弹充值门。
- verify 自身返回 402、额度码、或响应明确表示账户余额不足：视为明确额度证据，弹同一额度窗；不得把它当作网络失败放行。
- verify 超时、5xx、非 JSON、网络断开、Host 未挂载或无法解析余额：预检结果为 `unknown`，**放行实际请求**，不弹充值门。实际请求若返回一期定义的额度证据，仍弹同一门；其它错误保持原有错误展示。
- 预检过程不得自动重试实际操作；verify 最多由共享 inflight 合并，超时后由用户再次点击触发下一次尝试。预检不得形成“无限转圈”或锁死 CTA。

## 4. 触发矩阵（进页 / CTA / 不预检）

“进页”指 Tab 已打开、页面即将开始首个计费 fetch 之前；不是鼠标悬停或侧栏渲染前的无条件全局请求。“CTA”指会导致计费云调用或外部账号写入的明确点击。所有通过预检的操作仍必须保留一期失败后的 QuotaGate。

| 表面/插件 | 典型计费操作 | 触发时机 | 预检结论不足时 | 不预检范围 |
|---|---|---|---|---|
| `omnimux-analytics` 数据分析 | 概览、洞察、粉丝、帖子首 fetch；同步 | 侧栏进入后，Tab 已可见且**首个计费 fetch 前**预检；“立即同步/刷新”点击时预检 | 阻止首 fetch/同步，弹统一门 | 查看已加载内容、筛选/切换展示 Tab（触发新云 fetch 的瞬间仍需预检） |
| `omnimux-accounts` 账号 | 首次账号列表读取；连接账号；断开/修改账号、Agent 开关 | 页面首个云列表 fetch 前预检；连接/断开/修改等 CTA 点击时预检 | 列表不发起；写操作不发起，弹统一门 | 本地筛选、排序、查看已缓存账号；创建项目不相关 |
| `omnimux-publish` 发布中心 | 账号读取、上传/预签名、提交发布、发布刷新/重试 | 页面首个需要云数据 fetch 前预检；“上传/发布/刷新/重试”等 CTA 点击时预检 | 不上传、不预签名、不提交/重试，弹统一门 | 草稿本地编辑、选择素材、查看已加载记录；本地媒体选择不预检 |
| `omnimux-inspiration` 灵感库 | 云灵感列表/详情/创建/编辑/删除、云分析/视频理解 | 页面首个云列表 fetch 前预检；创建/编辑/删除/分析 CTA 点击时预检 | 云读写/分析不发起，弹统一门 | 本地灵感、已加载内容浏览、纯本地筛选 |
| `omnimux-workflow` 画布生成 | 图片/视频/音频生成节点提交；显式节点重试 | 用户点击“生成/运行节点/重试”时预检，不因打开画布或创建节点预检 | 节点不提交，保持可编辑并呈未执行/可重试态，弹统一门 | 画布打开、节点编辑、连线、保存本地项目、创建项目本地文件夹；本地剪辑/资产处理 |
| Chat（DSH LLM 面） | 会话发消息（会扣聊天额度） | 本期**不新增客户端 precheck**；继续使用 Harness/一期 turn 结束额度识别与现有 QuotaGate | 由实际请求/turn 失败处理；不在发送前另起一套门 | Agent 对话工具调用仍只返回结构化错误 |
| `omnimux-products` 产品库 AI | AI 文案/卖点、AI 图片或其它未来计费辅助 | P1 能力实际接入后，在发起 AI 云调用的 CTA 前预检 | 不发 AI 请求，弹统一门 | 产品本地 CRUD、导入/查看/筛选本地产品不预检 |
| `omnimux-assets` 资产库 | 当前无 OmniMux 计费入口 | 不预检 | 不适用 | 文件导入、搜索、查看、删除及磁盘操作 |
| `omnimux-clip` 剪辑工坊 | 当前本地 OpenReel 管线 | 不预检 | 不适用 | 剪辑、解码、波形、预览、导出 |
| 插件市场 | 本地目录/SkillHub 安装网络 | 不预检 | 不适用 | 浏览、安装、更新市场内容；不把通用网络错误误报余额 |
| Agent 官方工具/工作流 Agent 路径 | `omnimux_*`、工具侧 text/media/analytics 等云调用 | 不预检，不调用客户端额度门 | 工具返回一期结构化 `QUOTA`/`quota-exceeded`，`retryable:false` | Agent 不弹窗；不因同一错误再触发客户端门 |
| 创建项目 | 本地文件夹创建 | 不预检 | 不适用 | 全部本地项目创建流程 |

> 连接账号首屏列表属于云读取，因此纳入“进页预检”；“连接账号”写入授权属于 CTA 预检。账号授权页本身不内嵌收银台，也不由预检接管。

## 5. 交互（与现有 QuotaGate 关系、关闭后页面态、充值回来）

### 5.1 与一期 QuotaGate 的关系

- 预检和实际请求失败都只调用现有 `window.__omnimuxQuota.notify(...)`，共享同一标题“可用额度不足”、说明、主 CTA“去充值”、钱包 URL、2 秒冷却和既有登录门互斥规则；不新增第二个 modal。
- 预检通过只代表“最后一次 verify 观察到余额为正”，不改变请求、扣费或业务成功定义。实际请求返回 402、`insufficient_user_quota`、预扣费失败或其它一期额度证据时，仍必须通知同一门。
- 同一操作需携带稳定的 operation/correlation 标识。预检已打开门后，紧接着到达的同一操作 402 不再重复弹；同一时刻多个入口合并一个门。跨多阶段生成（submit/poll/download）仍只通知一次。
- 2 秒冷却继续沿用一期：关闭后短时间内的同一失败不重复弹，但不得吞掉业务失败结果。冷却不是余额缓存 TTL。

### 5.2 关闭弹窗后的页面态

- 关闭、ESC、遮罩关闭均不重试、不清除失败原因，不自动执行原 CTA。
- 页面保留可浏览的本地内容和已加载的静态/历史内容；不因余额不足把整个应用锁死。
- 被阻断的读请求：分析页保持空白/首屏占位并显示既有失败/额度状态，不能伪造新鲜数据；若已有成功缓存，允许继续查看缓存旧数据，并明确标为非实时，不自动刷新。
- 被阻断的写请求：表单草稿、选择项、画布节点和可编辑上下文保留；原 CTA 可再次点击，但每次点击都要重新执行预检。可按 UI 既有规范置为“暂不可执行”直到门关闭，但不得永久禁用。
- 画布节点保持未执行或可重试状态，不创建假成功文件；发布保持草稿/未提交，不产生重复任务；账号连接保持未连接。

### 5.3 去充值与充值回来

- “去充值”复用一期钱包 URL 规则：优先使用可信已登录 `profile.base_url` 安全拼接 `/wallet`，否则 `https://omnimux.ai/wallet`；沿用一期打开外部钱包的方式。
- 返回应用不推断支付成功，不自动刷新余额，不自动重试原操作，也不恢复被阻断的请求。
- 用户回到应用后重新点击原 CTA（或分析页明确的“刷新/重试”）才触发一次新的 `verify=1`；余额更新后再放行。预检失败且用户关闭门后同样需要用户主动再次点击。
- 若用户在另一窗口充值，另一窗口最多在下一次受保护入口或显式刷新时获取新 verify；不以轮询钱包或跨窗口猜测到账状态为本期要求。

## 6. P0/P1/P2 + Given/When/Then

### P0（必须）

- 共享 verify 数据源、30 秒成功结果复用、inflight 合并、登录/多窗口失效规则。
- `quota_usd <= 0` 明确阻断；正余额、未知费用不误判不足；预检传输失败 fail-open。
- 分析进页首 fetch 前预检；账号连接/写操作、发布 CTA、灵感云写/分析 CTA、画布生成 CTA 预检。
- Chat 不新增发送前预检；Agent 不弹窗；本地资产、剪辑、市场、创建项目不预检。
- 预检门与一期 QuotaGate 单门、同钱包、2 秒冷却、同操作去重；实际 402 仍兜底。
- 关闭后保留失败态/草稿/节点上下文，不自动重试；返回钱包需用户再次点击。

### P1（应该）

- 余额大于 0 但低于产品可配置的提示阈值时，在 Profile/已有余额展示处提供非阻断低余额提示。
- 预检/放行/阻断/兜底 402 的匿名埋点：能力、入口、结果、耗时、是否点击充值；不得记录 prompt、token、账号密钥或原始响应。
- 跨 Tab 可见的最近一次额度更新时间和“数据可能非实时”提示；可访问性和中英文文案完整覆盖。
- products AI 能力正式接入时补齐 CTA 预检，不提前为当前本地 CRUD 加门。

### P2（可以）

- 钱包返回后的用户主动“刷新余额”按钮及低余额趋势提示。
- 基于云端可靠估价的费用预估和“余额覆盖本次操作”提示；在此之前不得假装有估价。
- 预检命中率、误阻断率、402 兜底率和充值转化漏斗看板。

### Given / When / Then

- **Given** 分析 Tab 已可见但首个计费 fetch 尚未开始，**When** 预检 verify 返回 `quota_usd: 0`，**Then** 不发起该 fetch，弹统一额度门，并保留分析页可恢复状态。
- **Given** 用户点击“连接账号/发布/生成”，**When** 预检返回正余额，**Then** 只放行本次原操作一次；预检不替代请求后的 402 处理。
- **Given** 预检返回正余额后另一窗口消耗完额度，**When** 实际请求返回 402，**Then** 仍弹同一额度门，不显示第二扇门、不自动重试。
- **Given** verify 请求超时或 Host 返回 5xx，**When** 用户点击计费 CTA，**Then** 不弹“余额不足”，按正常流程发起一次实际请求；实际额度错误再由一期门处理。
- **Given** 用户未登录，**When** 点击需预检的入口，**Then** 先打开登录门；登录成功后不自动重放，用户再次点击才预检/执行。
- **Given** `quota_usd` 为 `null` 且无额度错误证据，**When** 预检结束，**Then** 结果为 unknown 并放行，不把未知当不足。
- **Given** 用户关闭额度门，**When** 回到分析页/画布/发布页，**Then** 不重试；已缓存历史数据可查看，写操作上下文和失败态保留。
- **Given** 用户点击“去充值”并返回，**When** 未再次点击原 CTA，**Then** 不刷新余额、不发原请求；再次点击才强制 verify。
- **Given** 同一按钮被连续点击或进页重复触发，**When** 预检尚未完成，**Then** 只保留一次 verify 和一次原操作意图，不重复云调用或弹窗。
- **Given** Agent 工具或 Chat 发生额度错误，**When** 错误返回客户端，**Then** Agent 只得到结构化额度错误；Chat/turn 沿用一期兜底，不新增 precheck modal。

## 7. 非目标

- 不删除、替换或弱化一期 402/预扣费失败后的 `window.__omnimuxQuota` 弹窗。
- 不将 precheck 变成计费授权、扣费、费用估价或云端余额锁定；不修改云计费。
- 不为每个插件创建 modal、充值页或独立 HTTP 客户端；不新增 Settings section；不让垂直 import hub。
- 不内嵌收银台、不确认外部支付到账、不自动重试原请求。
- 不对本地资产、剪辑/预览/导出、市场、产品本地 CRUD、创建项目或普通网络错误做余额预检。
- 不对 Agent 工具弹客户端窗；不把 Chat 本期改造成发送前预检；不以视频费用未知为由阻断所有生成。
- 不要求当前未合入的 Profile quota refresh worktree 作为前置条件。

## 8. Open Questions（≤5，带产品建议）

1. **30 秒成功 verify 复用窗口是否适配首批线上流量？** 产品建议先按 30 秒上线，以降低多 Tab 重复请求；若 402 率或余额陈旧投诉升高，再缩短到 10 秒，不改变 fail-open 与一期兜底。
2. **P1 低余额提示阈值是否采用固定金额？** 产品建议首期不拍固定金额，先只采集正余额分布；有数据后按能力/用户群设阈值，避免把“低”误说成“不够”。
3. **钱包返回后的“刷新余额”入口放在哪里？** 产品建议首期复用原 CTA 的再次点击；P1 在统一门关闭后的业务失败态旁增加明确“重试前检查余额”动作，但仍不自动执行。
4. **Chat 是否在后续纳入发送前预检？** 产品建议本期不纳入，待 Harness 提供稳定的发送前额度查询语义和延迟预算后单独立项；当前保持 turn 尾额度门。

## 9. 给架构师的锁定决策

1. 预检属于 `omnimux` 拥有的客户端能力，垂直只能消费既有全局 seam/封装，不 import hub、不自建门或钱包逻辑。
2. 权威预检数据是 `status?verify=1` 的公开 `quota_usd`；普通缓存只能加速登录/展示，不能证明额度足够；成功结果最多复用 30 秒并合并 inflight。
3. P0 阈值固定为 `quota_usd <= 0`；无法可靠估价（含视频）时不做费用比较，正余额即通过，最终以云端 402 为准。
4. 明确的余额不足响应阻断原操作并调用现有 `window.__omnimuxQuota`；verify 超时、网络/5xx/不可解析等 unknown 必须 fail-open，由实际请求和一期 402 兜底。
5. 未登录优先 `__omnimuxAuth.ensureLogin()`；登录成功、充值返回均不自动重试，必须用户再次点击；沿用一期登录互斥、2 秒冷却和 wallet URL 规则。
6. 数据分析在 Tab 可见且首个计费 fetch 前预检；连接/发布/生成/灵感云写操作在 CTA 前预检；Chat 和 Agent 不新增客户端 precheck。
7. 预检与 402 共享 operation/correlation 去重，确保进页重复 fetch、按钮连点、预检命中后 402、多阶段 media 只显示一扇门。
8. 阻断只影响本次计费请求：保留本地浏览、缓存历史（标非实时）、表单草稿、发布草稿和画布可编辑/失败态；不伪造成功、不清空上下文、不触碰本地 CRUD。
